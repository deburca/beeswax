# Release 1.9.1

Animated groups no longer risk staying invisible, the build is reproducible with CI, and several small theme leftovers are fixed.

## Highlights
- A `group` with an animation is hidden only while scripting is on and reduced motion is not requested; without JavaScript, or if the script fails, the content is shown (after a 4s timer in the failure case).
- A group taller than the screen now animates in (it used to need to be wholly in view).
- Groups added to the page after load (AJAX, Canvas preview) animate too, and the animation plays once rather than on every scroll back.
- Visitors who ask for reduced motion get the content with no movement.

- The compiled CSS no longer picks up class names from documentation and notes (about 1.7 KB of unused rules gone), so `build/` only changes when the theme does.
- Dismissing a status message always removes it from the layout, even with reduced motion or no transition, and keyboard focus moves to the next message.
- Removed a call to a breadcrumb library that was never defined.
- A site that copies `fonts.css` to the web root is told how to fix the font paths, and the theme no longer preloads its own fonts in that case.
- The footer and Canvas detection now declare their cache dependencies (footer year no longer stale after New Year), the Canvas lookup is not repeated within a request, and the theme settings page no longer stacks an info message each time it is rebuilt.
