# Release 1.9.5

Fixes from a review of the theme's interface, interactions and design patterns ([[ui-and-interaction-review]]): visible keyboard focus, a dark-mode pager, accessible menus, accordions and video, one source for colours, and print and forced-colour support. The review read the source; the live checks listed at the end have not been done.

## Highlights
- **Keyboard focus is visible everywhere.** One 2px pine outline now shows on anything that takes focus, and the form fields, the HiveLog fields and Tom Select draw a real outline instead of a pale tint (which was close to invisible).
- **Forms:** the focused label and select text no longer turn pale; error text and the required asterisk use the theme's red (it was `red-500`, under 4.5:1); a chosen select value no longer looks like a placeholder.
- **Pager:** the current page is readable in dark mode (it was white on near-white) and is marked `aria-current="page"`.
- **Status messages** follow the palette and dark mode, with a coloured edge and icon per type; info messages are blue (not pine). They span the width on phones and no longer block the page around them.
- **Mobile menu:** the toggle reports open and closed (`aria-expanded`), Escape closes it, the page behind it is inert while it is open, and focus returns to the toggle. `aria-current` marks only the current page. The default call-to-action block no longer ships two `example.com` buttons.
- **Accordion:** closed panels are hidden from screen readers and the tab order, every panel is readable without scripting, and resize listeners are cleaned up.
- **Video:** the play/pause control has a dark disc and a focus outline, its labels are translatable, an autoplaying video always has a pause control and pauses itself under reduced motion, and captions can be supplied (new props).
- **Page structure:** the page title is inside `<main>`, the skip link lands on `<main>`, redundant ARIA roles are gone, only one breadcrumb is printed, and its label is translatable.
- **Colours:** every colour is written once in `theme.css`; status colours (`ok`, `info`, `warning`, `critical`, with tints) and `field-border` are Tailwind names; `npm run check:colours` and `npm run check:twig` run in CI.
- **Preferences:** the page sends `color-scheme` and `theme-color` for the chosen scheme, filled buttons and the pager keep an edge in forced-colour modes, and printing uses light ink and drops the navigation, floating controls and messages.
- **Touch:** on touch screens the HiveLog controls grow to 44px (checkboxes and radios to 24px).

## Upgrade notes
- **If you copied `theme.css` to the web root, copy it again** (and merge your changes). It now holds the whole palette: the shadcn names are aliases of the `--bw-*` tokens, and `--bw-field-border`, `--bw-info`, `--bw-info-tint` and the honey tokens (`--bw-honey*`, `--bw-on-honey`) live there. A stale copy has no `--bw-field-border` (it used to be in `hivelog.css`), so HiveLog field borders would disappear.
- **Page layout changes.** The breadcrumb and page title moved from `<header>` into a `.beeswax-page-head` block at the top of `<main>`, so on pages whose primary menu, secondary menu, breadcrumb, highlighted or help regions are filled, the title now appears below them. The `role="banner"`, `role="main"`, `role="complementary"` and `role="contentinfo"` attributes are gone. Site CSS that selects `header[role="banner"]` or `footer[role="contentinfo"]` must use `.beeswax-page-head` and `footer`; the theme's own selectors are updated. If you place the breadcrumb block in the Breadcrumb region, the header no longer prints a second one.
- **Visible changes to check:** headings set to the *Accent* colour are pine (they were the pale tint, about 1.2:1); info messages are blue; dark-mode red is slightly lighter (`--destructive` follows `--bw-critical`, `#e8756c`); form focus has an outline.
- **Menus:** a site that relied on the navbar's default "Button" and "Another" example buttons now sees none; fill the CTAs slot. `aria-current` on the main menu is now `page` on the current link only, and is no longer set on a parent in the active trail.
- **Vinculum app (`Palette.swift`):** add `--bw-info` (`#2b5f8f` light, `#7db4e3` dark), `--bw-info-tint` (`#e4eef7`, `#1d2935`) and `--bw-field-border` (`#8f8575`, `#7d7360`) where relevant, and drop its separate dark destructive value (use critical).
- **The *Match the device* setting** says in its description that it needs JavaScript; with scripting off the page stays light. If you changed `--bw-ground`, change the two `theme-color` values in `templates/layout/html.html.twig` too.
- **New video props** `captions_src`, `captions_lang`, `captions_label`; the pause control now also appears whenever `autoplay` is on.
- **Button component:** a `<button>` now has `type="button"` (it no longer submits a surrounding form).
- **Not renamed:** `--accent` is still the pale tint and `--primary` the solid pine; `CUSTOMIZING.md` has a *Tokens* section.
- **Contributors:** run `npm run check:twig` and `npm run check:colours` with the other checks; both run in CI. Decisions: [[0001-token-architecture-and-source-of-truth]] (accepted), [[0002-focus-and-interaction-state-pattern]] and [[0003-interactive-component-accessibility-contract]] (proposed).
